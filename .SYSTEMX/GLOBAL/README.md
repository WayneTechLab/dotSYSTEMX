# Global context

Here, **Global means shared by every agent in this active project**. Keep stable
project-wide identity, constraints, terminology, accepted sources, and common
operating expectations in [CONTEXT.md](CONTEXT.md).

Organization-wide or multi-project standards can be referenced there with their
source, version, scope, and last review date. Import only the applicable approved
rules. A pointer to another repository does not import its task history, private
data, or execution authority, and this template does not sync external memory.

Separate responsibilities:

- Global context: what the whole team must know before choosing work.
- [Master plan](../PLAN/MASTER-PLAN.md): where the project is going and why.
- [Task ledger](../WORK/TASKS.json): who owns work and its current state.
- [Project memory](../MEMORY/PROJECT.md): what has been learned and verified.
- Agent memory: what one worker needs to resume its scoped assignment.

Agent 0 maintains shared context from accepted project facts. Avoid copying
task status or entire plans into this file.

When applicable, keep reviewed access decisions in the blank
[access matrix](ACCESS-MATRIX.md) and open it only for permission work. It does
not grant real access. A source-backed [project map](../PLAN/MAP.md) can point
to systems and boundaries without duplicating the task ledger. See the
[access and map guide](../docs/ACCESS-AND-MAP.md).
