# Two copyable .SYSTEMX prompts

These examples describe two stages of one authorized project workflow. They are not the three arms of the token-count fixture. Replace the bracketed fields with your project facts. An application or connector must provide actual access to the chosen files.

## 1. Initial brief: establish the project and first accepted milestone

```text
I am building a twenty-page web application for [audience] so they can [concrete outcome]. The project is at [authorized repository or local directory]. Its important constraints are [stack, accessibility, security, budget, schedule, and existing work to preserve]. My available tools and allowed external actions are [actual tools and authority].

Use the exact canonical .SYSTEMX folder. Inspect the current checkout, selected defaults, applicable instructions, and existing records. If adoption is needed, review the public WayneTechLab/dotSYSTEMX template and a pinned release, preview setup, and preserve existing project files. Select one explicit root or named .SYSTEMXP scope. Do not create a second .systemx folder or copy another project's private memory.

Begin with a useful first milestone: accepted requirements, the page inventory, shared interfaces, and a verifiable vertical slice. Research primary sources where needed; retain concise findings, source dates and URLs, uncertainty, and the decisions they support. Record the objective and constraints in GLOBAL/CONTEXT.md, outcomes and acceptance in PLAN/MASTER-PLAN.md, and independently owned work in the canonical task ledger. Use actual returned task/request IDs.

Have Agent 0 coordinate the work. Delegate dependency-ready tasks only when available host subagents or a selected installed CLI can help, with distinct write scopes and an agreed resource budget. Agent Y is the separate CLI lane; enable a draft PR only when explicitly authorized for that task. Keep acceptance, merge, and cleanup gates separate. Activate optional records deliberately. Use Agent X for meaningful observed events, Agent Z to assess supplied evidence against its fixed policy, and Agent Alpha for relevant AUTOBOT references.

Where ROOT is adopted, retain explicit bindings and actual harness or bot observations. Reconcile only relevant differences through authorized tools, then read back. Run appropriate project checks and useful negative checks; record original outputs and exact revisions. Finish the milestone's authorized work, report remaining gaps, and leave a bounded checkpoint with the next action. Do not treat a score, CLI exit, URL, or external completion message as accepted delivery or live verification.
```

Short on-screen version:

```text
Audience + outcome + constraints
Authorized sources + tools + budget
First accepted milestone
Canonical tasks + clear ownership
Evidence + review + checkpoint
```

## 2. Bounded follow-up: complete the next task without replaying the project

```text
Continue [TASK-ID] in [explicit root or Project-A/.SYSTEMXP scope] toward [milestone/outcome]. The observed source revision is [exact revision or an honestly labeled gap]. The next acceptance condition is [observable result]. Keep the existing objective, source hierarchy, and permission boundaries.

Confirm the selected defaults, current focus, task owner, dependencies, relevant memory, and latest original evidence. Read the bounded task packet and only the additional sources required for this task. Confirm actual source state before writing. Preserve unrelated edits and records.

Use the available harness to perform the next authorized action. If a separate CLI is useful, prepare one Agent Y handoff with the selected installed provider, repository/base, non-overlapping write scope, evidence requirements, resource limits, and stop condition. A draft PR is allowed only if already authorized for this task. Do not label a graphical example or provider-free fixture as an executed Codex job.

Retain changed-file and original-check evidence, including a relevant negative check when it helps establish the acceptance condition. Record significant observed events with Agent X. Use a matching Agent Z policy/evidence review when appropriate; do not rerun unchanged reviews or tests without a concrete concern. Agent 0 or the user accepts done against the criteria.

Compare relevant SYSTEMX, harness, and optional bot observations where ROOT is adopted. Apply justified changes through their actual tools, read them back, and retain unresolved access or freshness gaps. Return the result, evidence, limitations, and exact next action. Checkpoint at the agreed boundary and continue independent authorized work if one part is blocked.
```

Short on-screen version:

```text
Select task + scope + revision
Read the bounded packet
Perform the next authorized action
Check + review + reconcile
Checkpoint the remaining delta
```
